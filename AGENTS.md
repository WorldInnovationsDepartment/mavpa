# AGENTS.md

mavpa is an **agent harness first**. An agent (Claude Code, Codex, or anything that reads
skills) does the musical detective work, the Python toolbox measures, draws and builds, and
`song.json` is the contract between them.

## If you were asked to monkey a track
Follow `skills/mavpa/SKILL.md`. It has the whole workflow, the gates and the pitfalls. Run
the toolbox with `bin/mavpa <command>` (it creates its own environment on first run).

## If you are working on mavpa itself

1. **Layout**
   1. `skills/mavpa/`: the skill (`SKILL.md`, `reference/*.md`, `scripts/mavpa` launcher).
      This is the product. Keep it accurate when commands change.
   2. `commands/`: Claude Code slash commands (`/mavpa:monkey`, `/mavpa:doctor`).
   3. `mavpa/`: the toolbox.
      1. Commands and setup: `cli.py`, `workspace.py`.
      2. Measuring and transcription: `tempo.py` (grid), `separate.py`, `analyze.py`,
         `transcribe.py`, `drums.py`.
      3. Pictures: `views.py`.
      4. Turning the analysis into a kit: `draft.py`, `spec.py` (song.json → notes),
         `build.py`, `guide.py` + `templates/guide.html`.
      5. Checks: `verify.py`, `doctor.py`.
   4. `.claude-plugin/`, `.codex-plugin/`, `.agents/plugins/`: plugin and marketplace manifests.
   5. `examples/make_demo.py`: an original demo song with ground truth.
2. **Invariants**
   1. Song bar 1 = the first downbeat. The kit adds `lead_in_bars` (1), so DAW bar = song
      bar + 1. Everything that writes MIDI goes through `Grid.daw_t`.
   2. Commands print evidence, not just answers. An agent has to be able to disagree with them.
   3. `mavpa build` only reads `song.json` and the stems. It must stay deterministic: the
      same spec gives the same kit, byte for byte.
   4. Never commit audio, stems or kits of third-party songs (`.gitignore` blocks audio
      files). The demo song is generated by `examples/make_demo.py`.
   5. Python that touches user audio runs with `-I` (the launcher does this).
3. **Checks before a commit**
   1. `python -m pytest tests -q` (fast, no models).
   2. `claude plugin validate .` (manifest).
   3. When the toolbox changes, run the demo end to end: `python examples/make_demo.py /tmp/demo`, then
      `bin/mavpa new /tmp/demo/demo.wav` → `separate` → `grid --write` → `analyze` → `draft` → `build` → `verify`.
      Compare with `/tmp/demo/truth.json` (100 BPM, 4/4, A minor, 8-bar loop, Am | Am/G | Fmaj7 | E7 | Am | C | Dm7 | E).
4. **Style.** Plain Python and numpy, few dependencies, functions over classes, numbered
   lists in docs.
